# 계정과 접근

## Decisions

- 사용자는 Supabase Auth의 이메일+비밀번호로 로그인한다. 소셜 로그인과 메일 링크(매직 링크) 로그인은 쓰지 않는다.
- 가입은 배포 환경변수에 둔 초대 코드를 아는 사람만 할 수 있다. 가입 시 이메일 인증 메일은 쓰지 않는다(Supabase "Confirm email" 끔). 초대 코드가 가입 문지기 역할을 한다.
- 위젯 JSON 주소는 사용자마다 따로 발급한 개인 토큰으로 연다. 공용 비밀 키를 쓰지 않는다.
- 설정, 푸시 구독, 발송 기록은 모두 한 사용자에게 속하고, 다른 사용자는 읽거나 바꿀 수 없다.

## Boundaries

- 로그인 방식을 영구히 고정하는 결정이 아니다. 아래 "Reconsider when" 조건이 생기면 다시 본다.
- 배포 위치, 저장소, 정시 발송 방식은 [hosting-and-scheduling](hosting-and-scheduling.md)이 정한다. 이 계약은 거기에 손대지 않는다.

## Why

iPhone 홈 화면에 추가한 앱은 Safari와 로그인 상태(쿠키·저장소)를 공유하지 않는다. 메일 링크로 로그인하면 링크가 Safari에서 열려 앱은 로그인되지 않으므로, 앱 안에서 입력해 끝나는 이메일+비밀번호를 골랐다.

Supabase 기본 메일 서버는 프로젝트 팀원이 아닌 주소로는 보내지 않고 시간당 2통으로 제한된다(2026-11-19 [Supabase 문서](https://supabase.com/docs/guides/auth/auth-smtp) 확인). 외부 SMTP를 붙이지 않는 한 친구에게 인증 메일을 보낼 수 없어서, 메일 인증을 쓰지 않고 초대 코드로 가입을 제한했다. 공개 주소에 가입을 그냥 열면 모르는 사람이 공공데이터 호출 한도와 무료 플랜을 나눠 쓰게 된다. 사용자(보람)가 확정했다.

## Reconsider when

- 외부 SMTP를 연결해 인증·비밀번호 재설정 메일을 보낼 수 있게 될 때
- 초대 코드가 유출돼 원치 않는 가입이 생길 때
- 가입자가 친구 몇 명 수준을 넘어 사용자별 한도나 관리 화면이 필요해질 때

## Still-rejected alternatives

- 메일 링크 로그인 — iPhone 홈 화면 앱에 로그인이 전달되지 않는다. 앱이 Safari와 상태를 공유하게 되면 다시 본다.
- Google 로그인만 — iPhone 홈 화면 앱에서 구글 화면이 Safari로 넘어갔다 돌아오는 과정에 로그인이 풀릴 수 있는데, 실기기 확인 전에는 맡길 수 없다.
- 누구나 가입 — 사용자 수를 통제할 수 없고 외부 호출 한도를 소진할 수 있다.
- 허용한 이메일 목록만 가입 — 통제는 정확하지만 친구가 늘 때마다 운영자가 목록을 고쳐야 한다.
